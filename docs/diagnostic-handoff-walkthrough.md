# Share a reviewed diagnostic handoff

This exercise creates a diagnosis using only the repository's synthetic fixture,
previews the redacted export, and imports it into a separate receiving store.
It requires Linux, Python 3, and a current WorldBisect source checkout. Run the
blocks in the same Bash session from the repository root.

## Create an example diagnosis

```bash
set -euo pipefail
umask 077
make build
work="$(mktemp -d)"
cp -R examples/file-cause "$work/good"
cp -R examples/file-cause "$work/bad"
cp "$work/good/config.good.txt" "$work/good/config.txt"
cp "$work/bad/config.bad.txt" "$work/bad/config.txt"

./bin/worldbisect capture --trace=off --store "$work/sender" \
  --workspace "$work/good" --oracle exit=0 --output "$work/good.wcap" -- ./check.sh
if ./bin/worldbisect capture --trace=off --store "$work/sender" \
  --workspace "$work/bad" --oracle exit=0 --output "$work/bad.wcap" -- ./check.sh; then
  echo 'Expected the synthetic bad check to fail' >&2
  exit 1
fi
test -s "$work/bad.wcap"
./bin/worldbisect compare --store "$work/sender" \
  --good "$work/good.wcap" --bad "$work/bad.wcap" --format json \
  -- ./check.sh > "$work/analysis.json"
analysis_id="$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["analysis_id"])' "$work/analysis.json")"
```

The failing capture deliberately returns nonzero while recording its evidence.
The comparison should report `PROVEN` for `config.txt`, within the tested model.
The analysis ID is generated by your run; no customer incident ID is needed.

## Sender: preview, review, then confirm

```bash
./bin/worldbisect handoff --store "$work/sender" \
  --analysis "$analysis_id" --preview
```

Preview is read-only: it does not write a `.wdiag` bundle. Review the listed
files, redacted fields, incident ID and retention guidance. It should report
`confirmation_required: true`. Redaction removes workspace content blobs,
command output and other sensitive fields, but the remaining operational
metadata still needs human review. A raw `.wcap` capture is a different artifact
and must not be substituted for the reviewed diagnostic handoff.

After that review, confirm the export:

```bash
./bin/worldbisect handoff --store "$work/sender" \
  --analysis "$analysis_id" --output "$work/diagnosis.wdiag" --confirm
```

For an actual handoff, send only the reviewed bundle through your approved
channel. Do not send the sender store, its private signing key or raw captures.
Confirmation creates a local export; this CLI command does not send a message.

## Receiver: import and verify

This separate store simulates a second engineer receiving the bundle:

```bash
received_id="$(./bin/worldbisect import --store "$work/receiver" \
  --certificate-output "$work/received.wbc" "$work/diagnosis.wdiag")"
./bin/worldbisect explain --store "$work/receiver" "$received_id"
./bin/worldbisect verify "$work/received.wbc"
```

Import validates the bundle and reports before persisting them. Successful
certificate verification exits zero and reports `valid: true`. Without an
independently obtained public key, the trust result is
`embedded key not independently trusted`: signature consistency alone does not
establish who sent it. When you have verified the sender's public key through
a separate trusted channel, use:

```bash
./bin/worldbisect verify --public-key /path/to/reviewed-sender-public.pem "$work/received.wbc"
```

If import or verification fails, stop using that evidence, read the error and
`next_action` where available, and obtain the complete original bundle or the
correct independently verified key. Do not edit a certificate to make it pass.
Even a valid certificate requires review of its model boundaries and retained
evidence; it does not establish a universal cause or recreate the historical host.

Delete the received bundle and exported certificate when your agreed retention
period ends. For this disposable exercise, remove its temporary directory:

```bash
rm -rf -- "$work"
```

See the [user guide](user-guide.md#export-and-import),
[proof boundary](proof-boundary.md), and `worldbisect --help` for the contracts
behind these commands. The same export/import/verify sequence is exercised by
the repository's packaged-release E2E test.
