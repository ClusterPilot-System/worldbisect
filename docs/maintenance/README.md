# Monthly release and maintenance notes

Publish one Markdown note here each month using `YYYY-MM.md` in UTC. Keep the
note short, factual, and linked to public commits, releases, issues, and pull
requests. A note should cover:

1. release identity and whether a release was actually published;
2. security, compatibility, CI, and documentation maintenance;
3. community activity and clearly scoped good-first-issue work;
4. consented anonymized user reports, or an explicit statement that none were
   published; and
5. the next month's bounded priorities and known limitations.

Do not copy private incident details, customer identifiers, raw captures,
secrets, or unverified claims into a note. The note is a public status record;
`ROADMAP.md`, release metadata, and executable checks remain authoritative.
